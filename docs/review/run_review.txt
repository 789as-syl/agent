  # 一、为什么我建议你这样部署

  结合你仓库当前代码看，有几个很关键的点：

  1. 前端是 Vite 静态站点
      - front/client
      - front/admin
        所以最适合 npm run build 后交给 Nginx 直接托管。
  2. 前端 API 现在写死成相对路径 /api/v1
      - front/shared/api/client-core.ts
      - front/shared/api/sse-client.ts
        这意味着最省事的办法是：
      - 用户访问 app.example.com
      - Nginx 把 app.example.com/api/... 反代到 FastAPI

  3. 两个前端都用了 BrowserRouter 根路由
      - front/client/src/App.tsx
      - front/admin/src/App.tsx

  upstream kb_api {

          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_request_buffering off;

  - admin.example.com
  - storage.example.com

  ## 第三步：构建前端

  你的前端是 Vite，直接构建即可：

  cd front/client
  npm ci
  npm run build

  cd ../admin
  npm ci
  npm run build

  构建后会得到：

  - front/client/dist
  - front/admin/dist

  ## 第四步：启动后端服务

  你现在生产环境至少要有这些服务：

  - api
  - worker
  - postgres
  - redis
  - minio
  - nginx

  你当前仓库里的 docker-compose.yml 只有 postgres / redis / minio，这还不够上线。
  生产至少还要补：

  - api
  - worker
  - nginx

  ## 第五步：生产环境变量要改

  重点改这些：

  APP_ENV=production
  DEBUG=false

  CORS_ORIGINS=https://app.example.com,https://admin.example.com

  JWT_SECRET_KEY=换成强随机密钥

  MINIO_ACCESS_KEY=不要再用默认值
  MINIO_SECRET_KEY=不要再用默认值
  MINIO_SECURE=true
  MINIO_ENDPOINT=storage.example.com

  ### 这里有个非常关键的点

  你项目里登录 cookie 在生产环境会走 secure=True。
  所以生产必须上 HTTPS，否则登录/刷新 token 会出问题。

  另外，你的 MinIO 预签名 URL 是后端生成给浏览器直传的。
  所以 MINIO_ENDPOINT 不能写成内网地址或 localhost，否则外部用户上传会失败。
  要写成用户浏览器能访问到的域名，比如：

  MINIO_ENDPOINT=storage.example.com

  # 4. Nginx 怎么配

  ## 4.1 用户端 app.example.com

  upstream kb_api {
      server 127.0.0.1:8000;
      keepalive 32;
  }

  server {
      listen 80;
      server_name app.example.com;
      return 301 https://$host$request_uri;
  }

  server {
      listen 443 ssl http2;
      server_name app.example.com;

      ssl_certificate     /etc/letsencrypt/live/app.example.com/fullchain.pem;
      ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

      root /srv/agent/front/client/dist;
      index index.html;

      client_max_body_size 50m;

      location /assets/ {
          expires 30d;
          add_header Cache-Control "public, immutable";
          try_files $uri =404;
      }

      # SSE
      location ~ ^/api/v1/conversations/.*/runs/.*/stream$ {
          proxy_pass http://kb_api;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_buffering off;
          proxy_cache off;
          gzip off;
          add_header X-Accel-Buffering no;
          proxy_read_timeout 3600s;
          proxy_send_timeout 3600s;
      }

      # 普通 API
      location /api/ {
          proxy_pass http://kb_api;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_read_timeout 300s;
          proxy_send_timeout 300s;
      }

      # SPA 路由回退
      location / {
          try_files $uri $uri/ /index.html;
      }
  }

  # 5. 为什么我不建议你现在把前端直接丢到 Vercel/Netlify

  可以，但你当前代码不太适合直接这么干，因为：

  1. API 地址现在是写死的相对路径 /api/v1
  2. SSE 也是相对路径
  3. 认证用 withCredentials
  4. MinIO 还有预签名上传

  所以当前代码最稳的是“前端和 API 同源”，也就是：

  - 用户访问 https://app.example.com
  - 前端请求 https://app.example.com/api/v1/...
  - 实际由 Nginx 转发给后端

  这样：

  - 不折腾 CORS
  - Cookie 最稳
  - SSE 最稳
  - 生产问题最少

  # 6. 你上线时最容易踩的坑

  ## 坑 1：把 admin 放到 example.com/admin

  你现在前端路由是根路径风格，不是子路径风格。
  直接放 /admin 很容易路由冲突。
  除非你去改 Vite base 和 React Router basename。

  所以当前更推荐：

  - app.example.com
  - admin.example.com

  ## 坑 2：生产还在用默认 MinIO 账号

  一定改掉。

  ## 坑 3：开发 compose 直接拿去公网

  你现在 compose 里把这些端口都暴露了：

  - 5432
  - 6379
  - 9000
  - 9001

  生产不要这样全暴露公网。
  公网 ideally 只暴露：

  - 80
  - 443

  数据库、Redis、MinIO 应该只走内网网络。

  ## 坑 4：SSE 被 Nginx 缓冲

  所以 SSE 那个 location 一定要：

  - proxy_buffering off
  - gzip off
  - X-Accel-Buffering no
